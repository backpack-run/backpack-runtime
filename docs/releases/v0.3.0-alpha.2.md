# Backpack Runtime v0.3.0-alpha.2

This prerelease radically simplifies Backpack around one task: running established AI coding workspaces on curated open models.

## Highlights

- Replaces the split between `backpack run <model>` and `backpack launch <agent>` with `backpack run <app>`.
- Makes Codex, Claude Code, OpenCode, Pi, Codex App, and Claude App the primary product surface.
- Adds `backpack run list` and `backpack run doctor <app>` for app discovery and readiness diagnostics.
- Consolidates catalog, installed-model, inspection, and verification operations under `backpack models`.
- Removes Backpack's user-facing one-shot and interactive model-chat harness while retaining the loopback inference service and managed sessions required by coding apps.
- Keeps local and SSH compute, verified GGUF and llama.cpp installation, lifecycle cleanup, Cloud routing, and the OpenAI/Anthropic protocol adapters.
- Rewrites current documentation and release qualification around the coding-workspace workflow.

## Intentional CLI break

The alpha-only `launch`, `model`, `catalog`, `list`, `inspect`, and `hardware` top-level commands are no longer public. Use:

```console
backpack run codex --model qwen3-coder-30b-a3b
backpack run list
backpack run doctor codex --model qwen3-coder-30b-a3b
backpack models
backpack models installed
backpack models show qwen3-coder-30b-a3b
backpack models verify
```

There is intentionally no replacement for `backpack run <model> --prompt ...`. Coding workspaces own prompts, tools, repository access, and approvals; Backpack owns the inference/runtime layer beneath them.

## Qualification status

Codex CLI and Claude Code retain deterministic protocol/configuration coverage and prior real Cloud tool-loop evidence with Qwen3-Coder 30B A3B. OpenCode and Pi retain deterministic isolated-provider coverage but still require real-binary qualification. Desktop integrations remain experimental. A model is not exposed to an app unless trusted capabilities and app-specific compatibility admit it.

## Install or update

```powershell
backpack update --prerelease
```

New installations may use the checksum-verifying installers documented in `docs/install.md`.
